# outline — Format entry (framework default)

A hierarchical planning scaffold (design §5.2 — a platform-agnostic genre): an ordered
tree of sections and headings, each carrying a stated intent and a few bullet leads,
that a human edits BEFORE any prose is drafted and that renders unchanged to whatever
output type the deliverable coordinate selects (md, plain-text, pdf, epub).

Rhetorical structure (consumed at compose, §15):

1. **Title + one-line thesis** — what the finished piece will deliver or argue, in a
   single sentence the rest of the tree serves.
2. **Sections** — an ordered list of top-level headings, each with a one-clause intent
   (what this section must accomplish) rather than finished prose.
3. **Sub-points** — under each section, a short ordered list of the beats to cover, in
   reading order; nesting is allowed but kept shallow.
4. **Leads to verify** — where a point needs a source, the bullet names the lead, not an
   invented fact (INFERRED/AMBIGUOUS graph hits are leads to check, never published
   claims, §6.5).
5. **Open questions** — a trailing list of the gaps the author still owes, so the
   scaffold is honest about what it does not yet cover.

Discipline: an outline is STRUCTURE, not final copy — its bullets are editable intents,
and any factual lead carried into the drafted artifact must trace to the source
(EXTRACTED-tier, §6.5; never invented). Single-part genre: `parts` rides the schema
floor (Q14) — one outline is one artifact, never a composite. No platform data lives
here (Q4): the scaffold is not "for" any destination until the user routes it
(§8, §12.3).
